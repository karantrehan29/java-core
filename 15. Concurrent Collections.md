# Concurrent Collections (`ConcurrentHashMap`, `BlockingQueue`)

Concurrent collections provide thread-safe operations for common data structures. They are useful when multiple threads share data, but they do not automatically make a sequence of separate operations atomic.

## `ConcurrentHashMap`

`ConcurrentHashMap<K, V>` is a thread-safe map that supports concurrent reads and updates. It does not lock the entire map for every operation, so multiple threads can often make progress at the same time.

For updates, the implementation coordinates access to the relevant table bin (a bucket) rather than locking the whole map. In modern Java implementations, some updates use compare-and-set operations and contended updates may synchronize on a bin. This is an implementation detail; do not rely on every update simply locking a bucket.

Individual operations such as `put`, `get`, and `remove` are thread-safe. A multi-step check-then-act sequence is not automatically atomic:

```java
if (!map.containsKey(key)) {
    map.put(key, value);
}
```

Use an atomic map operation when the work is for one key:

```java
map.putIfAbsent(key, value);
map.computeIfAbsent(key, this::loadValue);
```

`ConcurrentHashMap` does not allow `null` keys or values. Its iterators are weakly consistent: they do not throw `ConcurrentModificationException`, but may reflect some updates made while iterating and are not a point-in-time snapshot.

## `BlockingQueue`

`BlockingQueue<E>` is a thread-safe queue designed for producer-consumer coordination. Its blocking methods wait when the operation cannot proceed:

- `put(element)` waits until space is available.
- `take()` waits until an element is available.
- `offer(element)` returns immediately with `false` if a bounded queue is full.
- `poll()` returns immediately with `null` if the queue is empty.

Timed variants, such as `offer(element, timeout, unit)` and `poll(timeout, unit)`, wait only for the specified duration. These methods can throw `InterruptedException`, so callers should handle interruption appropriately.

Bounded queues can provide backpressure by limiting how many tasks or items producers can enqueue. Common implementations include:

- `ArrayBlockingQueue`: bounded queue backed by an array.
- `LinkedBlockingQueue`: optionally bounded queue backed by linked nodes; specify a capacity when a bound is required.
- `PriorityBlockingQueue`: orders elements by priority, but is unbounded, so it does not provide capacity-based backpressure.

Example:

```java
BlockingQueue<String> queue = new ArrayBlockingQueue<>(100);

// Producer
queue.put("job");

// Consumer
String job = queue.take();
```

The queue safely coordinates access to its elements. It does not make unrelated shared state thread-safe.
