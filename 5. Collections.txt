The Java Collections Framework provides interfaces and classes for storing,
retrieving, and processing groups of objects using different data structures.

Core interfaces:
1. List: An ordered collection that allows duplicate elements.
2. Set: A collection that does not allow duplicate elements.
3. Queue: A collection used to hold elements before they are processed.
4. Deque: A double-ended queue that allows insertion and removal from both
	ends.
5. Map: Stores key-value pairs. Map is part of the Collections Framework but
	does not extend the Collection interface.

List implementations:
1. ArrayList: Fast random access; usually the default choice for a List.

ArrayList Example:
List<Integer> numbers = new ArrayList<>();
numbers.add(1);
numbers.add(3);
numbers.remove(Integer.valueOf(3));
Collections.sort(numbers);

// numbers now contains [1]

When using List<Integer>, remove(3) tries to remove the element at index 3.
Use Integer.valueOf(3) when you want to remove the value 3.

To access an element by index, use get(index):

Integer firstNumber = numbers.get(0); // Gets the element at index 0
Integer thirdNumber = numbers.get(2); // Gets the element at index 2

Indexes are zero-based, so index 2 means the third element. The list must
contain at least three elements, otherwise get(2) throws
IndexOutOfBoundsException.


2. LinkedList: Supports efficient insertion and removal at the ends; also
	implements Deque.

LinkedList Example:
LinkedList<Integer> numbers = new LinkedList<>();
numbers.add(1);
numbers.add(3);
numbers.addFirst(0);
numbers.addLast(5);

Integer firstNumber = numbers.getFirst(); // Gets 0
Integer lastNumber = numbers.getLast(); // Gets 5

numbers.removeFirst(); // Removes 0
numbers.removeLast(); // Removes 5

// numbers now contains [1, 3]

LinkedList supports efficient insertion and removal at both ends. However,
accessing an element by index, such as numbers.get(1), takes O(n) time.

Set implementations:
1. HashSet: Stores unique elements without guaranteeing iteration order.

HashSet Example:
Set<Integer> numbers = new HashSet<>();
numbers.add(1);
numbers.add(1);
numbers.add(2);

boolean containsOne = numbers.contains(1); // true
int numberOfElements = numbers.size(); // 2; duplicate 1 is ignored
numbers.remove(2);

for (Integer number : numbers) {
	System.out.println(number);
}

HashSet does not support get(index) because it does not provide positional
access. Use contains() to check for a value or iterate over the set.

2. LinkedHashSet: Stores unique elements and preserves insertion order.
3. TreeSet: Stores unique elements in sorted order.

Queue and Deque implementations:
1. PriorityQueue: Retrieves elements according to priority rather than
	insertion order.

Queue<Integer> maxElements = new PriorityQueue<>(Comparator.reverseOrder());
maxElements.offer(10);
maxElements.offer(3);
maxElements.offer(7);

Integer largest = maxElements.peek(); // 10
Integer nextLargest = maxElements.poll(); // Removes and returns 10

The default PriorityQueue is a min-heap, so the smallest element has the
highest priority. Comparator.reverseOrder() changes it into a max-heap.

For a custom class, compare by count first and name second:

class Frequency {
	String name;
	int count;
}

Comparator<Frequency> frequencyComparator =
		Comparator.comparingInt((Frequency item) -> item.count)
				.thenComparing(item -> item.name);

Queue<Frequency> frequencies = new PriorityQueue<>(frequencyComparator);

The comparator can also be written inline:

Queue<Frequency> orderedFrequencies = new PriorityQueue<>((first, second) -> {
	int countComparison = Integer.compare(first.count, second.count);
	if (countComparison != 0) {
		return countComparison;
	}
	return first.name.compareTo(second.name);
});

The comparator above sorts by count in ascending order. If two frequencies
have the same count, it sorts their names alphabetically.

Use Integer.compare(count1, count2) instead of count1 - count2 because
subtraction can overflow for extreme integer values.


2. ArrayDeque: Efficient double-ended queue implementation.
3. LinkedList: Can also be used as a Queue or Deque.

Map implementations:
1. HashMap: Stores key-value pairs without guaranteeing iteration order.

HashMap Example:

Map<String, Integer> frequency = new HashMap<>();
frequency.put("a", 1);
int aCount = frequency.get("a");
int bCount = frequency.getOrDefault("b", 0);
boolean isKey = frequency.containsKey("a");


2. LinkedHashMap: Preserves insertion order of entries.

3. TreeMap: Stores entries sorted by key.

4. ConcurrentHashMap: A thread-safe map designed for concurrent access.

Interface hierarchy:
Iterable
  -> Collection
		-> List
		-> Set
		-> Queue
			 -> Deque

Map is separate from Collection because it stores key-value pairs rather than
individual elements.

Common time complexities:
1. ArrayList: get by index is O(1); adding at the end is amortized O(1);
	inserting or removing in the middle is O(n).
2. LinkedList: adding or removing at either end is O(1) when the node is
	already known; accessing by index is O(n).
3. HashMap and HashSet: get, put, and remove are O(1) on average. Performance
	depends on a good hash function and correct equals() and hashCode() methods.
4. TreeMap and TreeSet: insertion, lookup, and removal are O(log n) because
	they use a balanced tree.
5. PriorityQueue: peek is O(1), while offer and poll are O(log n).

How HashMap works:
1. HashMap uses the key's hashCode() to calculate a bucket location.
2. If multiple keys map to the same bucket, a collision occurs.
3. HashMap uses equals() to find the correct key inside that bucket.
4. When the map becomes sufficiently full, it resizes and redistributes its
	entries. The default load factor is 0.75.
5. In modern Java implementations, heavily-collided buckets can be converted
	from linked nodes into balanced trees to improve lookup performance.

HashSet internally uses a HashMap. A set element is stored as a map key, so
correct equals() and hashCode() implementations are essential.

Ordering and null behavior:
1. HashMap and HashSet do not guarantee iteration order.
2. LinkedHashMap and LinkedHashSet preserve insertion order.
3. TreeMap and TreeSet maintain sorted order using natural ordering or a
	supplied Comparator.
4. HashMap permits one null key and multiple null values.
5. ConcurrentHashMap does not permit null keys or null values.

Concurrency:
1. ArrayList, HashMap, and HashSet are not thread-safe.
2. Collections.synchronizedList() and synchronizedMap() provide synchronized
	wrappers, but iteration still requires external synchronization.
3. ConcurrentHashMap supports concurrent access without locking the entire
	map for normal operations and does not allow null keys or values.
4. CopyOnWriteArrayList is useful when reads greatly outnumber writes because
	each write creates a new copy of the underlying array.

Fail-fast iterators:
Most standard collection iterators detect structural modification during
iteration and throw ConcurrentModificationException. Use Iterator.remove(),
removeIf(), or a concurrent collection when modification during iteration is
required. Fail-fast behavior is a bug-detection mechanism, not a thread-safety
guarantee.

Choosing a collection:
1. Use ArrayList for frequent index access and general-purpose lists.
2. Use HashSet when uniqueness matters and ordering does not.
3. Use LinkedHashSet or LinkedHashMap when insertion order matters.
4. Use TreeSet or TreeMap when sorted data or range queries are required.
5. Use ArrayDeque for stack or queue behavior instead of the legacy Stack
	class.
6. Use PriorityQueue when the next element should be selected by priority.
7. Use ConcurrentHashMap when multiple threads need to access a map safely.
