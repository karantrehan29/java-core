# Immutability

Immutability means that an object's state cannot be changed after the object has been created. The state is initialized in the constructor and remains the same for the object's entire lifetime.

`String` is a common example of an immutable Java class. Any operation that appears to change a `String` actually creates and returns a new `String` object.

## Example

```java
public final class Student {
    private final int id;
    private final String name;

    public Student(int id, String name) {
        this.id = id;
        this.name = name;
    }

    public int getId() {
        return id;
    }

    public String getName() {
        return name;
    }
}
```

This class is immutable because:

1. The class is `final`, so it cannot be extended.
2. The fields are `private` and `final`.
3. The fields are initialized only in the constructor.
4. There are no setter methods.
5. The fields use immutable types: `int` and `String`.

## Guidelines for creating immutable classes

1. Make the class `final` so it cannot be extended.
2. Make all fields `private` and `final`.
3. Do not provide setter methods.
4. Make defensive copies of mutable objects received as inputs.
5. Return defensive copies of mutable objects instead of exposing internal state directly.

## Benefits of immutability

1. Immutable objects are naturally thread-safe because their state cannot change after construction.
2. They are safe to use as keys in `HashMap` or elements in `HashSet` because the values used by `equals()` and `hashCode()` do not change.
3. They are easier to reason about, test, and share between components.

## Java records (Java 16+)

Records automatically provide final fields, a constructor, accessors, `equals()`, `hashCode()`, and `toString()`.

```java
public record Student(int id, String name) {
}
```

Records provide shallow immutability. If a record contains a mutable field, such as a `List`, use a defensive copy such as `List.copyOf()` to protect it.
