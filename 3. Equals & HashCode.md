# equals() and hashCode()

`equals()` defines when two objects should be considered logically equal. `hashCode()` returns an integer used by hash-based collections such as `HashMap` and `HashSet` to organize objects efficiently.

## The equals() and hashCode() contract

1. If two objects are equal according to `equals()`, they must have the same hash code.
2. If two objects have the same hash code, they may or may not be equal.
3. If two different objects have the same hash code, a hash collision occurs. The collection then uses `equals()` to distinguish between them.
4. Whenever you override `equals()`, you should also override `hashCode()`.

## Example

In this example, two `Student` objects are considered equal when they have the same `id`. Therefore, `hashCode()` must be calculated from `id` as well.

```java
public class Student {
    private final int id;
    private final String name;

    public Student(int id, String name) {
        this.id = id;
        this.name = name;
    }

    @Override
    public boolean equals(Object object) {
        if (this == object) {
            return true;
        }

        if (!(object instanceof Student student)) {
            return false;
        }

        return id == student.id;
    }

    @Override
    public int hashCode() {
        return Integer.hashCode(id);
    }
}
```

## Interview trap: mutating a field used by hashCode()

If an object is stored in a `HashSet` and a field used by `equals()` or `hashCode()` is later changed, the object may no longer be found in the set.

Assume that `id` is mutable and has a `setId()` method:

```java
Set<Student> students = new HashSet<>();
Student student = new Student(1, "Alice");

students.add(student);
student.setId(2); // Changes the value used by hashCode()

students.contains(student); // May return false
```

The `HashSet` placed the object in a bucket based on its original hash code. It does not automatically move the object when the hash code changes.

To avoid this problem:

1. Prefer immutable objects as keys in `HashMap` and elements in `HashSet`.
2. Do not mutate fields used by `equals()` or `hashCode()` while the object is in the collection.
3. If mutation is necessary, remove the object first, mutate it, and add it again.
