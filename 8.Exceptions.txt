Exceptions in Java

1. What is an exception?

An exception is an object that represents an abnormal condition encountered
while a program is running. It interrupts the normal flow of instructions.
Examples include trying to parse invalid text as a number or trying to open a
file that does not exist.

If an exception is thrown, Java looks for a matching catch block. If none is
found in the current method, the exception propagates to the calling method.
This process continues up the call stack. If no caller handles it, the
exception is uncaught and the thread terminates. An uncaught exception on the
main thread may cause the application to stop, although other threads could
continue running.

2. Java's exception hierarchy

All exceptions and errors derive from Throwable:

Throwable
|-- Error
|-- Exception
    |-- RuntimeException

Error represents a serious problem, often related to the JVM or available
resources. Examples include OutOfMemoryError and StackOverflowError. Programs
usually should not try to recover from Errors.

Exception represents conditions an application may want to handle. Exceptions
are commonly divided into checked and unchecked exceptions:

- Checked exceptions are checked by the compiler. They must be caught or
  declared in the method signature with `throws`. They are Throwable subclasses
  that are not RuntimeException or Error subclasses. In typical application
  code, they extend Exception. Example: IOException.
- Unchecked exceptions are RuntimeException and its subclasses. The compiler
  does not require them to be caught or declared. They often indicate invalid
  input or a programming mistake. Examples: NullPointerException,
  IllegalArgumentException, and NumberFormatException.

3. Handling an exception with try and catch

Put code that may throw an exception in a `try` block. Handle a matching
exception in a `catch` block:

try {
    int number = Integer.parseInt("not a number");
    System.out.println(number);
} catch (NumberFormatException e) {
    System.out.println("The text is not a valid integer.");
}

The `NumberFormatException` is unchecked, so Java does not require this catch.
Handling it here lets the program respond with a useful message instead of
letting it propagate.

A method can have multiple catch blocks. Catch more specific exception types
before their more general parent types:

try {
    java.nio.file.Files.readString(java.nio.file.Path.of("data.txt"));
} catch (java.nio.file.NoSuchFileException e) {
    // Handle a missing file
} catch (java.io.IOException e) {
    // Handle another file input/output problem
}

4. Declaring or propagating exceptions with throws

Instead of handling an exception in a method, the method can declare that it
may pass the exception to its caller. This is required for checked exceptions
that the method does not catch:

static String readFile(String path) throws java.io.IOException {
    return java.nio.file.Files.readString(java.nio.file.Path.of(path));
}

The caller must then catch the IOException or declare it in its own `throws`
clause. Declaring `throws` does not itself throw an exception; it documents
that the method may pass one to its caller.

5. Throwing an exception with throw

Use the `throw` keyword to throw an exception explicitly. `throw` is followed
by an exception object:

static void validateAge(int age) {
    if (age < 0) {
        throw new IllegalArgumentException("Age cannot be negative.");
    }
}

`throw` throws an exception at a particular point in the code. `throws` appears
in a method declaration to list exceptions that may be passed to the caller.

6. The finally block

A `finally` block runs after the `try` and any matching `catch` block, whether
or not an exception occurred. It is commonly used for cleanup. It may not run
if the JVM or process terminates abruptly, so it is not an absolute guarantee.

try {
    // Work that may throw an exception
} catch (RuntimeException e) {
    System.out.println("The operation failed.");
} finally {
    System.out.println("Cleanup can go here.");
}

Avoid returning from a `finally` block because it can hide a return value or
exception from the `try` or `catch` block.

7. Try-with-resources

Use try-with-resources for objects that must be closed, such as files or
streams. The resource must implement AutoCloseable. Java closes it
automatically when the block exits, including when an exception occurs:

try (java.io.FileInputStream input =
         new java.io.FileInputStream("data.txt")) {
    int firstByte = input.read();
} catch (java.io.IOException e) {
    System.out.println("Could not read the file: " + e.getMessage());
}

8. Creating a custom exception

Create a custom checked exception by extending Exception, or an unchecked
exception by extending RuntimeException:

class InvalidOrderException extends Exception {
    InvalidOrderException(String message) {
        super(message);
    }
}

Use a custom exception when it gives callers a meaningful way to understand
and handle a specific condition in your application.

9. Good practices

- Catch the most specific exception you can reasonably handle.
- Do not silently ignore an exception; handle it, report it, or propagate it.
- Include useful context when reporting an error, but avoid exposing sensitive
  data.
- Use checked exceptions for conditions callers are expected to handle, and
  unchecked exceptions for programming errors or invalid method arguments.
- Do not use exceptions as ordinary control flow.
- Prefer try-with-resources over manually closing resources in `finally`.
