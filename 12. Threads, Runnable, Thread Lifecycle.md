# Threads

A thread is an independent path of execution within a process. Threads in the same process share its memory and other resources, while each thread has its own call stack.

Multiple threads can make progress concurrently. They run in parallel only when the runtime and operating system schedule them on different CPU cores at the same time; parallel execution is not guaranteed.

A race condition can occur when multiple threads access shared mutable state and the result depends on the timing or order of their operations. Protect critical sections that access shared state with synchronization or another suitable concurrency mechanism.

A deadlock occurs when threads wait indefinitely for one another to release resources, commonly because each holds a resource the other needs.

## Starting a thread

You can provide a `Runnable` to a `Thread`. Calling `start()` asks Java to schedule a new thread; that new thread then invokes `run()`:

```java
Runnable task = () -> System.out.println("Running on a new thread");
Thread thread = new Thread(task);
thread.start();
```

`Runnable.run()` takes no arguments and returns no value. Pass input to the task when creating it, rather than trying to pass arguments to `run()`.

For a small task, the lambda can capture a local variable. The captured variable must be final or effectively final:

```java
String message = "Hello from the new thread";
Runnable task = () -> System.out.println(message);
new Thread(task).start();
```

For a reusable task, store the input in a constructor:

```java
class PrintTask implements Runnable {
    private final String message;

    PrintTask(String message) {
        this.message = message;
    }

    @Override
    public void run() {
        System.out.println(message);
    }
}

new Thread(new PrintTask("Hello from the task")).start();
```

If the task needs to return a result, use `Callable<T>` instead. Its `call()` method can return a value, which is commonly retrieved through a `Future` when submitting it to an `ExecutorService`.

You can also extend `Thread` and override `run()`, though passing a `Runnable` is usually more flexible because the task is kept separate from the thread that executes it:

```java
class Example extends Thread {
    @Override
    public void run() {
        // Task performed by this thread
    }
}
```

Calling `thread.run()` directly is an ordinary method call. It runs on the current thread and does not start a new one. A `Thread` can be started only once.

## Thread lifecycle

Java exposes these `Thread.State` values:

- `NEW`: created but not yet started.
- `RUNNABLE`: executing or ready to execute; Java does not distinguish these as separate states.
- `BLOCKED`: waiting to acquire a monitor lock.
- `WAITING`: waiting indefinitely for another thread or action, such as after `join()` without a timeout.
- `TIMED_WAITING`: waiting for a limited time, such as during `sleep()` or timed `join()`.
- `TERMINATED`: the `run()` method has completed or ended with an uncaught exception.

These are observable states, not a promise of a specific scheduling order. Calling `start()` moves a thread out of `NEW`; once it is `TERMINATED`, it cannot be started again.
